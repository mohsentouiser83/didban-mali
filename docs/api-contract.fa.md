# قرارداد API جاری

بازبینی کد: ممیزی ۲۰۲۵/۱۱/۲۵ (پس از ثبت و پیاده‌سازی D35 و D36). [OpenAPI تولیدشده](../contracts/openapi.json) با برنامهٔ جاری ۲۸۱ مسیر و ۳۴۴ عملیات HTTP دارد. مرجع اجرا `apps/api/didban/api.py` و `routes/` است. روش‌های متفاوت روی یک مسیر جداگانه شمارش می‌شوند.

## قواعد مشترک

مسیرهای شرکتی زیر `/api/v1/companies/{company_id}` هستند. عضویت/مجوز در سرور کنترل می‌شود. نشست HttpOnly، CSRF برای تغییرهای وابسته به نشست و Idempotency-Key در مسیرهایی که آن را مطالبه می‌کنند لازم است؛ نسخه مورد انتظار در body یا If-Match طبق schema همان عملیات ارسال می‌شود. همه مسیرها یک قرارداد نسخه فرضی مشترک ندارند. مبلغ رشته دقیق لاتین IRR، مقدار ناموجود null و تاریخ مالی ISO است. خطای دامنه کد و پیام فارسی دارد و اسرار/stacktrace برنمی‌گرداند.

مسیرهای سابق `/modules` بازنشسته شده‌اند. مجوز و اعتبار دادهٔ هر گردش در همان حوزه اعمال می‌شود.

## وب‌هوک و مدارک

تلگرام `POST /api/v1/bots/telegram/webhook` و secret header؛ بله `POST /api/v1/bots/bale/webhook/{secret}`. امنیت webhook مستقل از کوکی است. وضعیت اتصال، مدرک، استخراج و تأیید نهایی سند جدا هستند. هیچ پاسخ مدل یا پیام آزاد مجوز ثبت نیست. [بات‌ها](bots.fa.md).

[وضعیت/شواهد](current-implementation.fa.md)، [گردش کار](workflow-contract.fa.md)، [کارهای باز](../todo.md).

مسیرهای `company-groups` و `consolidation` طبق تصمیم ۲۰۲۶/۱۱/۲۳ از برنامه و OpenAPI حذف شدند و دیگر API فعال نیستند.

## قالب‌های سامانه — ۲۰۲۶/۱۱/۲۳

`GET report-studio/definitions` پنج تعریف پیش‌فرض شرکت را نیز با `system_key` و `can_delete=false` برمی‌گرداند. دریافت تعریف، نوشتن DB ندارد. `PATCH report-studio/definitions/{id}` با اختیار write، CSRF، کلید تکرارپذیری و If-Match، همان تعریف را نسخه‌دار ذخیره می‌کند؛ اولین ذخیرهٔ قالب پیش‌فرض با نسخهٔ ۱، پاسخ نسخهٔ ۲ دارد. نسخهٔ قدیمی ۴۰۹ است. شناسهٔ شرکت دیگر پیش‌فرض این شرکت نیست و قابل دریافت/ویرایش نیست. DELETE برای تعریف‌ها ارائه نشده است. تغییرهای قالب، گزارش‌های رسمی یا snapshot داشبورد ثابت قبلی را بازنویسی نمی‌کنند.

جدول‌های پیش‌فرض از همان قرارداد data_table استفاده می‌کنند و `columns.format`، `total_count`، `reason` و `source` را نیز برمی‌گردانند. منبع هر جدول صریح است؛ تاریخ نامعتبر و فیلتر/گروه‌بندی ناسازگار خطای دامنه دارند. این تغییر مدل یا مسیر HTTP تازه‌ای ندارد.

## تولید کد داخلی — ۲۰۲۶/۱۱/۲۳

فیلدهای code در موجودیت‌های غیرحساب، employee_code، contract_number و number پیش‌فاکتور در ورودی ایجاد اختیاری‌اند؛ مقدار ارسالی کد خودکار را تغییر نمی‌دهد. `source_reference` عملیات و انبار نیز از الگو تولید و در پاسخ ایجاد برگردانده می‌شود. تغییر کد داخلی موجود از مسیر ویرایش اعمال نمی‌شود. ورود کدینگ خارجی از chart-preview/chart-import کد منبع را حفظ می‌کند. `snapshot.number` شماره ثابت سند جدید در پیش‌نمایش و خروجی ثبت است؛ sequence برای ترتیب/سابقه باقی است. الگوی غیرفعال خطای numbering_inactive می‌دهد.

در ساخت فاکتور بومی نیز reference اختیاری است؛ در نبود آن شماره از مرجع قطعی عملیات گرفته می‌شود. ارسال شمارهٔ ناسازگار با شواهد همچنان رد می‌شود.

## نوع طرف‌حساب — ۲۰۲۶/۱۱/۲۳

ایجاد کارت تجاری در `POST /companies/{company_id}/commercial/counterparties` به فیلد `type` نیاز دارد؛ مقدار فقط `supplier`، `customer`، `employee` یا `other` است. در PATCH نوع اختیاری است؛ حذف فیلد از درخواست نوع قبلی را حفظ می‌کند و null یا مقدار نامعتبر رد می‌شود. پاسخ کارت و فهرست شامل نوع است.

## کدینگ چهارسطحی، الگو و منع ثبت روی سرفصل بالادست — ۲۰۲۶/۱۱/۲۵

- `POST accounting/accounts` در زمان ساخت حساب ساختاریافته (`group` / `general` / `subsidiary` / `detail`) از الگوی کدینگ سلسله‌مراتبی پیروی می‌کند: گروه ۲ رقمی، کل ۴ رقمی (با پیشوند کد گروه)، معین ۶ رقمی (با پیشوند کد کل) و تفصیلی حداقل ۸ رقمی (با پیشوند کد معین). در نبود `code` هنگام ساخت سطح‌دار، سرور کد بعدی الگو را به‌صورت خودکار تولید می‌کند. نام‌های فارسی سطح در ورودی فایل پذیرفته می‌شوند.
- `PATCH accounting/accounts/{id}` نسخهٔ مورد انتظار را کنترل می‌کند. حذف فیلدهای کد یا ساختار از درخواست، مقدار موجود را حفظ می‌کند؛ تغییر کد ثبت‌شده، کد تکراری، الگوی نامعتبر، بالادست با سطح ناسازگار یا تغییر سطح دارای زیرمجموعهٔ ناسازگار رد می‌شود.
- `GET accounting/accounts` فیلترهای `level` (شامل `group`، `general`، `subsidiary`، `detail` و `unclassified`) و `parent_id` را پیش از صفحه‌بندی اعمال می‌کند. پاسخ‌های فهرست و ذخیره شامل `level`، `parent_id`، `parent_code`، `parent_name`، `has_children` و `postable` هستند.
- ثبت پیش‌نویس، عملیات، انبار و ثبت نهایی سند روی حساب `group` (`non_postable_account`) و هر حساب دارای زیرمجموعه (`non_postable_parent_account`) مسدود است؛ برگشت سندهای ثبت‌شدهٔ پیشین همچنان مجاز می‌ماند.
- `chart-preview` / `chart-import` ساختار صریح `level`، `parent_code` و تطابق الگوی کد را به‌صورت یک بسته بررسی و بر اساس ترتیب سطح وارد می‌کنند؛ لازم نیست ردیف بالادست پیش از فرزند در فایل باشد. کد و کد بالادست Excel باید متن باشند. فایل بدون سطح، حساب تعیین‌نشده می‌سازد. پیش‌نمایش با تغییر کدینگ/ساختار باطل می‌شود.
- قاعدهٔ تاریخی شماره‌گذاری `account` حفظ می‌شود ولی در فهرست شماره‌گذاری نمایش ندارد و ساخت حساب از الگوی سلسله‌مراتبی ۲/۴/۶/۸ رقمی استفاده می‌کند. سایر موجودیت‌ها همچنان شماره‌گذاری خودکار دارند.
