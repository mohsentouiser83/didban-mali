# قرارداد API ساخت تازه

قرارداد ماشینی اجرای جاری در `/openapi.json` ارائه می‌شود. منبع routeها `apps/api/didban/api.py` و schema درخواست‌ها `apps/api/didban/schemas.py` است. جدول endpointهای قرارداد فنی نسخه ۰٫۱، مرجع دامنه است؛ صرف درج یک مسیر در آن جدول، اجرای فعلی آن مسیر را اثبات نمی‌کند.

مسیرهای هویت در `/api/v1/auth` و شرکت‌ها در `/api/v1/companies` قرار دارند. منابع مالی با پیشوند `/api/v1/companies/{company_id}` محدود می‌شوند. نشست در کوکی HttpOnly نگهداری می‌شود. درخواست تغییردهندهٔ احرازشده باید توکن CSRF و `Idempotency-Key` داشته باشد؛ عمل نسخه‌دار باید نسخهٔ مورد انتظار را نیز ارسال کند. جزئیات نهایی header/body نسخه از OpenAPI اجرای جاری خوانده شود.

| حوزه | قرارداد رفتاری |
|---|---|
| هویت | ورود/خروج/بازیابی نشست؛ بدون ثبت‌نام عمومی؛ ایجاد حساب توسط مدیریت نصب |
| شرکت/عضو | کنترل عضویت جاری برای داده شرکت؛ مدیریت مجوز صریح تأیید فقط توسط مالک همان شرکت |
| دوره | ایجاد، مشاهده، ویرایش و حذف مستقل؛ بازه نامعتبر و تغییر تاریخ دوره استفاده‌شده رد می‌شود |
| نوبت/فایل | دریافت، پایان انتقال، وضعیت پایدار و سؤال دارای شاهد؛ سؤال ضروری مانع کل نوبت است |
| نتیجه | manifest ثابت و شاخص‌های دارای مقدار رشته‌ای یا null، وضعیت، دامنه، علت، اقدام و شواهد |
| تخصیص | جهت و نسخه فعال و ظرفیت آزاد تحت تراکنش بررسی می‌شوند؛ برگشت ممیزی‌شده است |
| گزارش | مشاهده و دانلود مستقل از تأیید؛ تأیید فقط همان نسخه با مجوز جاری |
| خروجی | PDF و Excel از همان manifest؛ اصل فایل فقط با مجوز شرکت |
| دستیار | گفت‌وگوی عمومی بدون الزام گزارش؛ پرسش مالی از facts همان manifest؛ سابقه اختیاری حداکثر ۱۲ پیام user/assistant؛ تغییر مالی از متن گفتگو مجاز نیست |
| اتصال بات | کد یک‌بارنمایش، شروع در چت خصوصی، تأیید احرازشده و قطع اتصال نسخه‌دار؛ webhook مستقل از کوکی با secret ارائه‌دهنده |

مبلغ JSON رشتهٔ عددی لاتین در واحد کانونیکال IRR است؛ نمایش تومان داده ذخیره‌شده را تغییر نمی‌دهد. صفر معتبر از null جداست. کلیدهای `ledger`، `invoice` و اختلاف قابل مقایسه مبناهای مستقل‌اند و نباید با هم جمع شوند.

مسیرهای `bot-connections` فقط اتصال‌های خود کاربر در شرکت مجاز را کنترل می‌کنند. ایجاد اتصال به CSRF و idempotency نیاز دارد؛ کد خام در ذخیره replay باقی نمی‌ماند و فقط پاسخ اولیه آن را دارد. تأیید/قطع اتصال `If-Match` می‌خواهند. محدودیت اولیه هر حساب پیام‌رسان یک اتصال فعال است. مشخصات webhook، سقف پیام، وضعیت ارسال نامطمئن و حدود قابلیت در [قرارداد بات](bots.fa.md) آمده است. رابط شخصی اتصال‌ها در `/settings/connections` آماده است؛ وجود API و رابط، فعال‌سازی زندهٔ پیام‌رسان را اثبات نمی‌کند.

خطای دامنه دارای کد مشخص، پیام فارسی و status متناسب است. اطلاعات داخلی، مسیر فایل خصوصی، stacktrace و اسرار provider نباید به مرورگر بازگردند. حد صفحه‌بندی، خروجی دقیق هر route و enumها باید از نسخهٔ ماشینی قرارداد استخراج شوند.

پیکربندی بودجه نصب در `/api/v1/admin/model-budget`، تعرفه و آمادگی شرکت در `companies/{id}/model-tariffs` و `model-status` و مصرف/درخواست‌ها در `usage` و `model-requests` ارائه می‌شوند. هزینه نامعلوم در `model-reservations` دیده و فقط مدیر نصبِ مجاز شرکت می‌تواند مرجع بررسی و مبلغ واقعی را در مسیر `model-reservations/{id}/reconciliations` ثبت کند. کلید و انتخاب ارائه‌دهنده از محیط سرور‌اند؛ هیچ route مرورگر مقدار کلید را بازنمی‌گرداند.
