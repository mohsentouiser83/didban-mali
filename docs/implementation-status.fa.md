## فاز ۵ — نرمال‌سازی و مدل مالی یکپارچه

- صفحهٔ مستقل مدل مالی با نمایش آمادگی مدل کانونیکال، تراز اسناد و تحلیل سود و زیان

- feature flag سراسری و شرکتی با نمایش وضعیت مؤثر هر قابلیت
- API توضیح فارسی یافته فقط از شناسه یافته، reason code، اعداد مجاز و شناسه شواهد موجود
- API رتبه‌بندی فقط برای `potential_match`های ازپیش‌محدودشده موتور قطعی؛ بدون افزودن نامزد جدید
- خروجی‌های Pydantic با `extra=forbid`، الزام `requires_human_review=true` و سقف طول متن
- تطبیق همه اعداد متن و ارجاعات عددی با allowlist داده ساخت‌یافته، با پشتیبانی ارقام فارسی
- رد شواهد ناشناخته، تغییر مجموعه نامزدها، امتیاز اطمینان جدید و payload خارج از Schema
- timeout کنترل‌شده و شکست امن بدون توقف محاسبات، تطبیق، یافته‌ها یا گزارش قطعی
- ثبت append-only اجرای AI شامل purpose، نسخه prompt، provider/model، latency، outcome و شناسه شواهد؛ بدون chain-of-thought
- API مشاهده اجرای AI و idempotency برای تنظیمات و invocationها
- RLS کامل، کلیدهای خارجی مرکب، ایندکس‌های tenant-first و عدم مجوز UPDATE/DELETE برای سوابق AI
- عدم ارسال داده مالی به ارائه‌دهنده خارجی؛ provider پیش‌فرض `disabled` تا تصویب ارائه‌دهنده و محل پردازش

## فاز ۱۴ — E2E و آماده‌سازی دمو (بک‌اند)

**وضعیت:** محدوده بک‌اند تکمیل‌شده؛ Playwright و پذیرش بصری تا پیاده‌سازی رابط کاربری موکول است
**تاریخ:** ۱۴۰۵/۰۶/۲۲

### خروجی‌ها

- مولد seed نسخه‌دار و کاملاً ساختگی `demo-1405-v1` با خروجی تکرارپذیر
- فایل حسابداری، گردش سه حساب بانکی، فروش و دو variant خطادار CSV/XLSX
- manifest امضاشده SHA-256 شامل نسخه، فایل‌ها، اهداف تطبیق، findingها و ارقام golden
- حداقل ۲۰ exact clean با truth pair مستقل و precision اندازه‌گیری‌شده ۱۰۰٪
- پنج fuzzy قابل بررسی که هرگز به‌صورت خودکار تأیید نمی‌شوند
- دو نمونه golden از هر ۸ finding مصوب و اثبات نبود نوع نهم
- محاسبه مستقل ارقام دفتر seed: درآمد، سود و دارایی ۳۲۷٬۹۶۰٬۰۰۰ ریال و margin برابر ۱
- اثبات تکرارپذیری خروجی reconciliation و fingerprint یافته‌ها
- آزمون parse همه فایل‌های سالم و رد تاریخ/مبلغ خراب و formula در variantها
- فیلتر مرکزی log برای password، token، cookie، DSN، payload مالی و داده خام در API و worker
- مسیر integration کامل API از هویت و upload تا PDF، AI غیرفعال، audit و RLS
- راهنمای recovery برای PostgreSQL، Redis/worker، MinIO و ClamAV
- فرمان‌های `make seed-demo`، `make test-acceptance` و `make verify-backend`
- پرونده پذیرش ماشین‌خوان با وضعیت هر ۱۵ معیار و تفکیک موارد frontend
