# ممیزی منوی تنظیمات

## اصلاحات پس از ممیزی — ۲۰۲۶/۱۱/۲۲

- «شرکت و دسترسی» شامل مدیریت کاربران و اطلاعات شرکت است. اتصال پیام‌رسان‌ها در پروفایل کاربری در دسترس است و نشانی قدیمی به پروفایل هدایت می‌شود. در مرورگر، دو ورودی شرکت، جست‌وجوی تنظیمات، مسیر پروفایل و تغییر مسیر در عرض ۳۹۰ پیکسل بررسی شدند. ۱۲ آزمون وب مرتبط موفق بودند.

- چرخ‌دنده یک لینک مستقیم «اسناد» دارد. فایل‌های پردازش موجود، اصل ورودی‌های جدید جداول و کدینگ، و مدارک بات در همان صفحه دیده می‌شوند. نوبت‌های پردازش از اقدام مرتبط همان صفحه باز می‌شوند. اصل فایل‌های جدول و کدینگ فقط در شرکت جاری و برای بارگذار قابل مشاهده و دریافت است. رسانهٔ موقت دستیار و تصویر نمایه جزو اسناد شرکت نیستند. فایل‌هایی که پیش از این صرفاً در مرورگر پردازش می‌شدند و اصلشان ذخیره نشده بود، قابل بازیابی نیستند.
- تطبیق طرف‌حساب‌ها از خرید و فروش، تطبیق بانک از دریافت و پرداخت، و تطبیق کارپوشه از مؤدیان باز می‌شود. در صفحهٔ تطبیق مؤدیان، نبود فروش ثبت‌شده حالت خالی دارد و درصد در API برابر null است.
- کالا و انبار در سایدبار امکان ویرایش، غیرفعال‌سازی و حذف با تأیید دارند. حذف در صورت وجود پیش‌نویس وابسته یا گردش قطعی مسدود است. ارتقای راه‌اندازی تریگرهای قدیمی کاتالوگ را جمع می‌کند و تریگر حرکت قطعی را حفظ می‌کند.
- در مرورگر داخلی، لینک مستقیم اسناد، هر سه مقصد سایدبار، عنوان نبود فاکتور، صفحات کاتالوگ و آرشیو در عرض ۳۹۰ پیکسل بررسی شدند. فونت محاسبه‌شدهٔ تیتر، بدنه، کد لاتین و ارقام یکسان بود. عملیات تغییردهنده با دادهٔ ساختگی در آزمون API انجام شد. آزمون HTTP ویرایش و حذف کاتالوگ پس از نصب تریگرهای قدیمی، حفظ گردش قطعی، بازیابی اصل فایل و تفکیک بارگذار را پوشش داد. ۵۹۳ آزمون API و ۲۸۳ آزمون وب موفق بودند. یک آزمون PostgreSQL از مجموعه رد شد. TypeScript، ESLint، Ruff و بررسی diff موفق بودند.

## نتایج پیش از اصلاحات این دور — ۲۰۲۶/۱۱/۲۲

مرورگر داخلی روی نصب محلی ابتدا ۲۵ مقصد را باز کرد. پس از تصمیم کاربر، منو پنج دسته و ۱۵ مقصد دارد. مقاصد باقی‌مانده از خود منو باز شدند. در عرض ۳۹۰ پیکسل بازشدن با Enter، فوکوس جست‌وجو، بسته‌شدن با Escape و برگشت فوکوس بررسی شد. کالا، انبار و کاردکس از سایدبار باز شدند. هفت صفحهٔ حذف‌شده و صفحهٔ گروه قدیمی انبار در تنظیمات، صفحهٔ «پیدا نشد» نشان دادند. OpenAPI سرور محلی نیز ۲۶۷ مسیر داشت و APIهای اختصاصی بازنشسته را ارائه نکرد.

| مقصد چرخ‌دنده | عملیات موجود در وب و API | ارزیابی چرخهٔ عمر |
|---|---|---|
| کدینگ حساب‌ها | فهرست، تعریف، ویرایش، غیرفعال‌سازی، ورود کدینگ و تعیین نقش مالی در ویرایش حساب | غیرفعال‌سازی برای حفظ ارجاع اسناد کافی است. |
| دوره‌های مالی | ساخت، فهرست، ویرایش دورهٔ مجاز و حذف دورهٔ بدون وابستگی | حذف با وابستگی مالی در وب غیرفعال است و API آن را رد می‌کند. |
| ابعاد مالی | تعریف، فهرست، ویرایش و بایگانی یا فعال‌سازی | بایگانی سابقهٔ پروژه، شعبه و مرکز هزینه را حفظ می‌کند. |
| شماره‌گذاری | ساخت، فهرست، ویرایش و حذف قاعدهٔ سفارشی | قاعدهٔ سیستمی قابل ویرایش است و حذفش رد می‌شود. |
| کارمندان | ساخت، فهرست، ویرایش و حذف یا غیرفعال‌سازی طبق وابستگی | سیاست حذف باید سوابق پرسنلی وابسته را حفظ کند. |
| قرارداد کارمندان | ساخت، خواندن و ویرایش وضعیت و شرایط | گردش فعلی پایان یا تغییر وضعیت دارد. حذف مستقل فقط در صورت تعریف قرارداد آزمایشی یا اشتباه بدون اثر باید جداگانه بررسی شود. |
| دسترسی و کاربران | افزودن، فهرست، تغییر نقش، تغییر مجوز و قطع دسترسی | غیرفعال‌سازی عضویت ردپای اقدامات را حفظ می‌کند. آخرین مالک محافظت می‌شود. |

| اتصال‌ها و پیام‌رسان‌ها | وضعیت اتصال، ساخت کد، تأیید و قطع نسخه‌دار | گردش جفت‌سازی و قطع، چرخهٔ لازم است. |
| فایل‌های منبع | بارگذاری، فهرست، دریافت و بایگانی؛ حذف سخت مشروط در API | حذف سخت طبق D06 و پس از بررسی همهٔ وابستگی‌ها مجاز است. |
| نوبت‌های پردازش | ایجاد از بارگذاری، مشاهده، ثبت پاسخ و بازپردازش نسخه‌دار | چرخه با وضعیت نوبت و شواهد کنترل می‌شود. |
| مدارک بات | مشاهدهٔ صف، دستور ورود متنی، دریافت و ورود یا بازبینی استخراج | اصل خصوصی و تصمیم ثبت‌شده باید حفظ شوند. |
| تطبیق بانک و دفتر | ایجاد اجرای تطبیق، پیش‌نمایش، مشاهده و ثبت تصمیم | اصلاح از مسیر نسخهٔ تازه یا تصمیم مرتبط انجام می‌شود. |
| تطبیق طرف‌حساب‌ها | اجرای تطبیق با صورت‌حساب، مشاهده و ثبت تصمیم | سابقهٔ اجرا بازنویسی‌بردار نیست. |
| تطبیق کارپوشهٔ مؤدیان | گزارش خواندنی و تب‌های وضعیت | وضعیت خالی فاکتور نباید پیام «تمامی فاکتورها ارسال شده‌اند» بدهد. این پیام در نصب بررسی‌شده مشاهده شد. |

در سایدبار، مدیریت کالا و انبار به دفتر اصلی و مجوز مدیریت کاتالوگ وابسته است. فرم افزودن کالا به حساب فعال موجودی نیاز دارد. وب کاتالوگ عملیات ویرایش، غیرفعال‌سازی و حذف ندارد. در SQLite ایزوله، ساخت و فهرست کالا و انبار موفق بود. هر دو endpoint ویرایش و حذف برای رکوردهای بدون گردش خطای ۴۰۹ دادند. تریگرهای تغییرناپذیری روی جدول‌های کاتالوگ مانع عملیات‌اند. رفع مانع در طرح پایگاه و افزودن ویرایش و غیرفعال‌سازی در سایدبار لازم است. حذف فقط برای رکورد بدون وابستگی و با تأیید مناسب معنا دارد. کاردکس گردش حاصل از عملیات مالی را نمایش می‌دهد.

اعلان بات، موارد نیازمند بررسی، کنترل‌های دفتر، تحلیل مستقل تغییر هزینه، صفحهٔ مستقل نقش حساب‌ها، قواعد حسابداری و الگوهای ثبت/نگاشت از وب حذف شدند. انتشار اعلان زمان‌بندی‌شده، اجرای قواعد و اعمال الگوهای بازنشسته از کد اجرایی برداشته شدند. نقش مالی حساب از کدینگ و اخطارهای آمادگی بستن دوره از مسیر خودشان قابل استفاده‌اند. اصل مدارک، تاریخچه‌ها، کنترل نسخه و تفکیک شرکت‌ها حفظ شده‌اند.

مرورگر روی نصب موجود برای ناوبری، بازکردن فرم‌ها، حالت‌های خالی و کنترل‌ها استفاده شد. سرور جداگانهٔ SQLite ساختگی به‌دلیل خطای مجوز bind بالا نیامد. عملیات نوشتن با HTTP در TestClient و روی SQLite جداگانه آزمایش شدند. ساخت، فهرست، ویرایش و حذف دوره، رد نسخهٔ قدیمی، جداسازی شرکت و منع حذف دورهٔ وابسته موفق بودند. ذخیرهٔ نقش مالی حساب از API باقی‌مانده نیز موفق بود. در نصب مرورگر هیچ رکورد مالی، پیام، اظهار یا عملیات ثبت ایجاد نشد. راه‌اندازی مجدد worker نصب از این محیط به‌دلیل دسترسی‌نداشتن به Docker بررسی نشد.

پس از حذف‌ها، ۵۹۰ آزمون API و ۲۸۰ آزمون وب موفق شدند. یک آزمون نیازمند PostgreSQL اجرا نشد. TypeScript، ESLint، Ruff و بررسی diff موفق بودند.

## بررسی تاریخی ۲۰۲۶/۱۱/۰۱

گزارش این بخش به اجرای همان تاریخ مربوط است.


منوی چرخ‌دنده در هدر دسکتاپ و موبایل جای گروه مدیریتی سایدبار و انتخابگر جداگانه واحد نمایش را گرفت. مقصدهای شرکت‌های من، اعضا و دسترسی، دوره‌های مالی و مصرف و هزینه مسیرهای مستقل قبلی را حفظ می‌کنند. مقصد مدل هوش مصنوعی فقط به مدیر نصب نمایش داده می‌شود؛ ورود مستقیم دیگر کاربران نیز کنترل‌های مدیریت را نمایش نمی‌دهد و API پیکربندی نصب، مجوز مدیر نصب را مستقل بررسی می‌کند.

واحد نمایش فقط ریال یا تومان است. انتخاب در مرورگر و به تفکیک شناسه کاربر حفظ می‌شود؛ داده اصلی مالی و واحد ورودی تغییر نمی‌کنند. صفحه شرکت‌های من فهرست شرکت‌های مجاز و انتخاب شرکت فعال را دارد. ساخت شرکت همچنان فقط در اختیار مدیر نصب است.

صفحه مستقل مدل وضعیت مشترک نصب، بودجه کل نصب و تعرفه/آمادگی و درخواست‌های شرکت فعال را دارد. نام مدل پشتیبانی‌شده، کلید و فعال‌سازی از محیط سرور خوانده می‌شوند؛ انتخاب مدل دلخواه یا واردکردن کلید از مرورگر اضافه نشده است. هیچ درخواست زنده‌ای به provider انجام نشد.

## بررسی انجام‌شده

- مرورگر داخلی Codex: منوی دسکتاپ ۱۴۴۰×۱۰۰۰ و موبایل ۳۹۰×۸۴۴؛ لینک فعال، نشان انتخاب واحد، تغییر واحد، حفظ انتخاب پس از reload، Escape و بازگشت فوکوس، بازکردن منو با ArrowDown و رفتن به صفحه شرکت‌ها با Enter.
- شرکت‌ها: نمایش دو شرکت ساختگی و انتخاب شرکت بدون داده؛ هدر و اطلاعات شرکت به انتخاب تازه تغییر کردند.
- مدل: پاسخ موفق وضعیت نصب، بودجه، آمادگی، تعرفه و درخواست‌ها در پایگاه آزمایشی تازه؛ حالت‌های خالی نمایش داده شدند. فرم بودجه با ارسال خالی پیام فارسی و فوکوس فیلد الزامی داشت؛ بودجه واقعی ثبت نشد.
- حساب مشاهده‌گر ساختگی: گزینه مدل در منو غایب بود؛ مسیر مستقیم `/settings/model` پیام محدودیت دسترسی داشت.
- Reduce Motion سیستم‌عامل موقتاً روشن شد: `matchMedia` برابر true، انیمیشن منو `none` و `transition-property` گزینه‌ها `none` بود. تنظیم سیستم سپس خاموش و viewport آزمایشی بازنشانی شد.
- خطای API نیز پیش از راه‌اندازی API تازه بررسی شد؛ اقدام تلاش دوباره قابل دسترسی بود. پایگاه QA قبلی با تغییرات جدید مدل داده سازگار نبود؛ داده یا schema آن تغییر نکرد. آزمون موفق با پایگاه ساختگی جدید `var/settings-qa/browser-qa.db` و فایل‌های مستقل اجرا شد. پایگاه اصلی و قدیمی بازنشانی نشدند.
- build تولیدی شامل TypeScript موفق؛ ۱۸ آزمون وب و lint موفق؛ ۵ آزمون API مدیریت مدل موفق. fixtureهای tooltip با شناسه الزامی سری در نسخه نصب‌شده Recharts هماهنگ شدند.
