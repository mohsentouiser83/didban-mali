# بسته اعتبارسنجی بازسازی — نسخه ۱

تاریخ: ۲۰۲۶/۱۰/۲۵. تمام نام‌ها، شناسه‌ها و مبالغ **مصنوعی** هستند. این بسته برای بررسی قراردادها و ساخت آزمون‌های پروژه تازه است؛ داده مشتری، نتیجه اجرای محصول یا تأیید حسابدار نیست. مبلغ‌های کوچک عمداً انتخاب شده‌اند تا محاسبه دستی آسان باشد.

## از کجا شروع کنیم؟

۱. فایل `expected/reference-results.xlsx` را برای بررسی مالی باز کنید؛ پنج شیت خلاصه، مانده‌ها، پیش‌بینی، تطبیق مؤدیان و ملاحظات دارد. اعداد مرجع ثابت‌اند تا با تغییر فرمول موتور، انتظار آزمون بی‌صدا تغییر نکند.
۲. فقط **هشت فایل پوشه `inputs/baseline`** یک نوبت بارگذاری اصلی را تشکیل می‌دهند. پوشه‌های دیگر را همراه آن بارگذاری نکنید. فایل‌های مرجع، JSON و این راهنما ورودی کاربر نیستند.
۳. زمینه شرکت، دوره، پوشش و پاسخ‌های لازم در `scenarios/baseline-context.json` است. در برنامه آینده، این اطلاعات از تنظیمات شرکت، تفسیر معتبر یا پاسخ کاربر می‌آید؛ خودکار و از روی نام فایل فرض نمی‌شود.
۴. پیش از پاسخ دو سؤال، انتظار `waiting_input` و ممنوعیت انتشار نهایی است. خروجی نهایی مرجع فقط پس از پاسخ معتبر هر دو سؤال قابل مقایسه است.
۵. `expected/baseline.json` مرجع ماشینی مستقل و `expected/metric-observations.json` نمونه ساختار خروجی پیشنهادی API است. این نمونه، OpenAPI نهایی یا قرارداد پیاده‌شده نیست.

شناسه‌های خوانا مثل `company-a` در سناریوها نام مستعارند؛ `scenarios/identity-aliases.json` نگاشت آن‌ها به UUIDهای ثابت نمونه‌های API را نگه می‌دارد. شناسه منبع مثل `S001` با شناسه داخلی فاکتور یکسان فرض نشود.

تاریخ‌های اصلی میلادی‌اند: دوره جاری ۲۰۲۶/۰۹/۰۱ تا ۲۰۲۶/۰۹/۳۰ و دوره قبل ماه اوت. فایل‌های Excel اصلی سلول تاریخ واقعی دارند؛ CSV تاریخ متنی دارد و تقویم شمسی در نمونه نامنظم جدا آزموده می‌شود. کامل‌بودن منابع و مالیات صفر اوت، اظهار صریح سناریو هستند؛ نباید از نبود ردیف مالیات یا کمینه/بیشینه تاریخ استنباط شوند. شناسه‌های مالیاتی صرفاً کلید مصنوعی مقایسه‌اند و اعتبار مقرراتی/کارپوشه آن‌ها آزموده نشده است.

پوشش فاکتور شامل همه اقلام باز افتتاحیه و همه فاکتورهای سپتامبر است. فاکتور فروش نقدی تسویه‌شده اوت در این فایل نیست؛ این منبع برای فروش فاکتوری کل اوت کامل اعلام نشود. مقایسه مانده باز پایان اوت همچنان با اقلام افتتاحیه و تاریخچه معتبر ممکن است.

## نمونه‌های مرزی و قراردادها

- `inputs/edges`: واحد نامعلوم، سربرگ نامنظم و تاریخ شمسی، خطاهای تاریخ/مبلغ/دقت، فایل کاملاً تکراری، هم‌پوشانی مبهم، CSV خراب و متن شبیه فرمول/دستور. خروجی هرکدام در `scenarios/edge-expectations.json` است. نمونه‌های مخرب واقعی، ماکرو و بمب فشرده‌سازی در بسته نیستند.
- `scenarios/F01.json` تا `F15.json`: ورودی کانونیکال و انتظار هر پانزده قرارداد مالی. این JSONها برای آزمون دامنه‌اند؛ فایل قابل بارگذاری رابط نیستند. آزمون parser جداست. F11 ظرفیت مجاز را تعریف می‌کند؛ مسابقه واقعی تراکنش در این بسته اجرا نشده است.
- `scenarios/T01.json` تا `T14.json`: مراحل و انتظار آزمون‌های فنی، همگی با وضعیت `specified_not_executed`. به محصول تازه، پایگاه داده و محیط آزمون نیاز دارند. پاسخ مدل نامعتبر نیز صرفاً mock است؛ API مدل فراخوانی نشده است.
- `scenarios/decision-acceptance.json`: انتظارهای تکمیلی تصمیم‌های D01–D08 پس از بازبینی قراردادها؛ شامل منبع ناقص، ارز خارج از دامنه، طبقه‌بندی خودکار، اختیار مشاور، تأیید/اعطای مجوز، بایگانی و مقصد ساخت. همگی تعریف‌شده و اجرا‌نشده‌اند و جزو ۳۱۸ کنترل سازگاری فایل‌ها نیستند. تصمیم‌های ثبت‌شده در [سند بازبینی](../../rebuild-decision-review.fa.md) آمده‌اند.
- `inputs/capacity`: دقیقاً ده CSV، هرکدام دو هزار ردیف؛ بیست هزار گردش با مرجع یکتا، واریز و برداشت هرکدام ۱۰۰٬۰۰۰ و مانده صفر. این‌ها یک حساب مصنوعی با افتتاحیه صفر هستند. بارگذاری آن‌ها **نوبتی مستقل** از نمونه اصلی است. ساخت داده بار، آزمون پنج کاربر هم‌زمان محسوب نمی‌شود.
- `expected/invalid-rows.csv` و `formula-text-safe-export.csv`: نمونه خروجی خطا و خروج امن متن فرمول‌مانند؛ فایل ورودی اصلی تغییر نمی‌کند.
- `expected/forecast-daily.json`: گسترش روزانه پیش‌بینی کنترل‌شده؛ روزهای بدون رویداد نیز مانده دارند.

## اجرای بررسی مستقل

در محیط دارای Python و `openpyxl`:

```bash
python3 docs/validation/rebuild-v1/verify.py
```

این اسکریپت فایل‌های Excel ذخیره‌شده را فقط می‌خواند و با Decimal توازن اسناد، گردش/مانده بانک و دفتر، فاکتورها، مؤدیان، مبنای پیش‌بینی، اعداد مرجع و ظرفیت فایل‌ها را کنترل می‌کند. انتظارهای اصلی در JSON ثابت‌اند؛ اسکریپت آن‌ها را بازنویسی نمی‌کند. ردیف‌های خلاصه Excel نیز با JSON مقایسه می‌شوند. JSON پیش‌بینی روزانه و گزارش بررسی بازتولید می‌شوند.

`validation-report.json` گزارش **سازگاری فایل‌های نمونه** است؛ قبولی موتور مالی/فنی پروژه جدید نیست. سناریوهای ناموجودی داده و محدودیت ظرفیت بخشی مشخصات‌اند؛ صرف وجود آن‌ها، اجرای کنترل محصول را اثبات نمی‌کند. پیش‌نمایش همه شیت‌های ساخته‌شده بررسی شده است. نمایش عددی برخی شناسه‌ها در پیش‌نمایش ابزار ممکن است صفر اول را پنهان کند؛ بررسی فایل ذخیره‌شده حفظ مقدار متنی را کنترل می‌کند.

## باقی‌مانده برای پذیرش ساخت

۱. حسابدار اعداد و دامنه این نمونه و سیاست‌های باز قرارداد مالی را تأیید یا اصلاح کند؛ نسخه انتظارها و علت تغییر ثبت شود.
۲. چند خروجی مجاز و بی‌نام واقعی از بانک‌ها و نرم‌افزارهای هدف به نمونه‌ها اضافه شود؛ این بسته پشتیبانی همه قالب‌ها یا XLS قدیمی را ثابت نمی‌کند.
۳. پس از تعیین مقصد ساخت تازه، adapter آزمون، خروجی موتور را با همین مرجع مقایسه کند؛ F01–F15 و سپس T01–T14 در محیط واقعی اجرا شوند.
۴. سقف بایت/حجم بازشده، نقش‌های پیشنهادی، معیار کفایت تاریخچه، سیاست خطای تاریخ و منابع سرور با آزمون و تأیید نهایی شوند. تعریف دستی آستانه در این داده، تأیید محصول نیست.
